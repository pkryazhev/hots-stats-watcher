# hots-stats-watcher

Консольная утилита для Heroes of the Storm: следит за папками с реплеями,
автоматически определяет по BattleTag из конфига победу/поражение в новых
матчах и ведёт счётчик побед/поражений **в рамках текущего запуска**
(перезапустили — счётчик обнулился). Счёт пишется в текстовый файл, который
можно подключить как источник текста в OBS.

Героя пока не выводит в OBS-файл (по договорённости — добавим позже), но
внутри уже парсится и виден в консоли.

## Установка

Нужен только Python 3.8+. Дополнительные пакеты ставить не нужно — библиотеки
для чтения реплеев (`mpyq`, `heroprotocol` от Blizzard) уже лежат в папке
`vendor/`.

## Настройка

1. Скопируйте `config.example.json` в `config.json`.
2. `battletags` — список ников (BattleTag, без `#1234`), за которыми следим.
   Можно перечислить несколько — например, если у вас несколько аккаунтов.
3. `auto_discover_accounts_root` — путь до папки `Accounts` (без указания
   конкретного аккаунта). Стандартный путь на Windows:

   ```
   C:\Users\<вы>\Documents\Heroes of the Storm\Accounts
   ```

   На Mac обычно:

   ```
   ~/Library/Application Support/Blizzard/Heroes of the Storm/Accounts
   ```

   Утилита сама обойдёт эту папку и найдёт внутри все `Replays\Multiplayer`
   — по одному на каждый Battle.net-аккаунт, залогиненный на этом
   компьютере (папки вида `Accounts\<ID аккаунта>\...`). Указывать
   конкретные ID аккаунтов или пути к каждому из них не нужно — если
   появится новый аккаунт или изменится структура папок, утилита подхватит
   это сама при следующем запуске. К какому именно из ваших `battletags`
   относится новый матч, определяется не по папке, а по имени игрока внутри
   самого реплея (см. раздел ниже) — так что несколько аккаунтов работают
   "из коробки".

4. `replay_folders` — необязательный список конкретных папок
   `Replays\Multiplayer`, если нужно отслеживать что-то вне
   `auto_discover_accounts_root` (например, нестандартный путь установки).
   Можно использовать вместе с `auto_discover_accounts_root` или вместо
   него.
5. `toon_handles` — необязательный список уникальных ID аккаунтов (вида
   `"1-Hero-1-123456789"`) на случай, если у двух разных игроков совпадает
   BattleTag и матч по имени начинает путаться между ними. Как заполнить:

   - Запустите утилиту как обычно, с заполненным `battletags`.
   - Когда она найдёт совпадение по имени, рядом с конфигом появится файл
     `known_players.txt` со строками вида:
     ```
     # ВашНик - карта: Cursed Hollow (2026-09-08 21:14:03)
     "1-Hero-1-123456789",
     ```
   - Скопируйте нужную строку в кавычках в массив `toon_handles` в
     `config.json`.

   Если `toon_handles` непустой, утилита сначала ищет совпадение по нему и
   только если ничего не нашлось — падает обратно на `battletags`. ID не
   меняется при переименовании BattleTag и однозначно определяет аккаунт,
   так что совпадение имени с чужим игроком больше не собьёт статистику.
6. `known_players_file` — путь до файла, куда сохраняются найденные
   `toon_handle` (по умолчанию `known_players.txt` рядом со скриптом).
7. `poll_interval_seconds` — как часто проверять папки на новые файлы
   (по умолчанию 20 секунд). Это просто чтение списка файлов в паре папок —
   нагрузка на систему исчезающе мала, даже 5 секунд ничего не изменят.
   Раз в 15-30 секунд более чем достаточно: реплей появляется только после
   окончания матча (матч в HotS идёт 15-25+ минут), так что секундная
   задержка в обнаружении никакой роли не играет.
8. `obs_output_file` — путь до текстового файла со счётом. Укажите его
   в источнике "Текст (GDI+)" / "Text (FreeType 2)" в OBS через опцию
   "Читать из файла".
9. `obs_format` — как форматировать строку в файле. По умолчанию:
   `Победы: {wins}   Поражения: {losses}`

## Запуск

```
python watch_replays.py config.json
```

(или просто `python watch_replays.py`, если `config.json` лежит рядом со
скриптом).

При старте утилита сканирует указанные папки и запоминает уже лежащие там
реплеи как "старые" — они не учитываются. Считаются только матчи, реплеи
которых появились уже после запуска. Ctrl+C — остановить, в консоли будет
выведен итог сессии.

## Как определяется победа/поражение

В `replay.details` каждого реплея хранится список игроков с полем `m_name`
(BattleTag на момент матча), `m_toon` (неизменный ID аккаунта: регион,
programId, realm, id) и `m_result` (1 — победа, 2 — поражение, 0 — результат
не зафиксирован, обычно если игрок покинул матч раньше времени). Утилита
сначала пытается найти игрока по `toon_handles` из конфига (если он
непустой), и только если совпадений не нашлось — сравнивает `m_name` со
списком `battletags` (без учёта регистра). Берётся `m_result` совпавшего
игрока.

**Важный нюанс:** в реплее хранится именно отображаемое имя BattleTag на
момент игры, а не ID аккаунта. Если вы переименуете BattleTag или совпадёте
ником с другим игроком, поиск по `battletags` может ошибиться. Решение —
`toon_handles` (см. пункт 5 в «Настройке»): это стабильная привязка по ID
аккаунта, которая не зависит от текущего имени и не путается при совпадении
ников.

## Заказ героя за баллы канала Twitch

Зрители заказывают героя наградой за баллы канала: при активации награды
Twitch просит ввести текст — туда пишется имя героя. Утилита сама создаёт
эту награду на канале при первом запуске (название, стоимость и подсказка
берутся из конфига) и раз в несколько секунд проверяет новые активации:

- герой распознан и доступен — заказ встаёт в очередь, бот пишет в чат
  «заказ героя … принят»;
- герой не распознан (опечатка) или недоступен для заказа (`orderable:
  false`) — активация отменяется, **баллы автоматически возвращаются**
  зрителю, бот пишет об этом в чат.

Заказ автоматически считается выполненным, если в следующем реплее
отслеживаемый аккаунт (тот же `battletags`/`toon_handles`) сыграл именно
этим героем — тогда активация на Twitch тоже отмечается выполненной.
Один матч закрывает только один заказ на героя: если героя заказали дважды,
первым выполняется более ранний заказ, второй — в следующем матче на нём.
Лимитов на количество заказов нет — ограничителем служит стоимость награды.

**Заказы сохраняются между запусками** в файле `orders.json`
(`orders_storage_file`): очередь, накопленная на одном стриме, никуда не
денется после перезапуска утилиты. Активации, сделанные, пока утилита не
запущена, тоже не теряются — они обработаются при следующем запуске.
Редактировать `orders.json` руками стоит только при остановленной утилите
(иначе она перезапишет ваши правки). Если заказ нужно снять, проще
обработать его активацию (выполнить/отклонить) в очереди запросов наград на
Twitch — утилита заметит это и уберёт заказ из очереди.

Команда `!очередь` доступна всем без ограничений и выводит в чат список ещё
не выполненных заказов (выполненные в список не попадают).

Команда `!герои` доступна всем без ограничений и выводит в чат ссылку на
таблицу со списком героев (`heroes_link_url`).

Фича выключена по умолчанию (`orders_enabled: false`). Чтобы включить:

0. Награды за баллы канала доступны только каналам со статусом
   **компаньона (Affiliate) или партнёра**.
1. Заведите отдельный Twitch-аккаунт для бота (через него идут сообщения в
   чат). Желательно сделать его **модератором** канала — так на него не
   действуют медленный режим и строгие лимиты сообщений.
2. Получите `Client ID` и `Client Secret` — это учётные данные не бота, а
   вашего приложения (регистрировать можно под любым Twitch-аккаунтом, не
   обязательно под ботом):
   - Откройте [dev.twitch.tv/console/apps](https://dev.twitch.tv/console/apps)
     и войдите под своим Twitch-аккаунтом (Twitch требует включённую
     двухфакторную аутентификацию на аккаунте, чтобы регистрировать
     приложения — если её нет, сайт попросит включить).
   - Нажмите **"Register Your Application"**.
   - **Name** — любое уникальное имя (Twitch не даст сохранить, если такое
     имя уже занято другим разработчиком — если ругается на дубликат,
     добавьте что-то своё, например название канала).
   - **OAuth Redirect URLs** — нажмите "Add" и впишите ровно
     `http://localhost:17563/callback` (без опечаток и без слэша в конце —
     именно этот адрес слушает `twitch_auth_setup.py`).
   - **Category** — "Chat Bot".
   - **Client Type** — обязательно **"Confidential"** (у "Public"-приложений
     Twitch не выдаёт Client Secret).
   - Нажмите "Create".
   - Откройте созданное приложение через "Manage" — на этой странице сразу
     виден **Client ID**. Кнопкой **"New Secret"** сгенерируйте
     **Client Secret** и сразу скопируйте — Twitch показывает его только
     один раз, при следующем открытии страницы будет виден только Client ID.
3. Получите `twitch_refresh_token` — **один раз** запустите:
   ```
   python twitch_auth_setup.py
   ```
   Введите `Client ID`/`Client Secret`, когда попросит (если они уже есть в
   `config.json`, скрипт возьмёт их оттуда). Скрипт откроет ссылку
   авторизации Twitch — её нужно открыть **под аккаунтом бота** (не своим
   основным!) и разрешить доступ. После подтверждения скрипт сам запишет
   `twitch_client_id`/`twitch_client_secret`/`twitch_refresh_token` в
   `config.json` (если `config.json` ещё не создан — выведет их, чтобы
   скопировать вручную). Дальше
   `watch_replays.py` сам обновляет `access_token` по мере необходимости
   (в т.ч. сохраняя новый `refresh_token` обратно в `config.json`, если
   Twitch его меняет) — повторно проходить через браузер не нужно.
3а. Получите `twitch_broadcaster_refresh_token` (токен **канала** — нужен,
   чтобы создавать награду, читать её активации и возвращать баллы):
   ```
   python twitch_auth_setup.py broadcaster
   ```
   `Client ID`/`Client Secret` скрипт возьмёт из `config.json` (из шага 3),
   а ссылку авторизации нужно открыть **под аккаунтом канала (стримера)**.
   Полученный `twitch_broadcaster_refresh_token` скрипт сам запишет в
   `config.json`. При запуске утилита проверяет, что токен выдан именно
   аккаунту `twitch_channel`.
4. Заполните в `config.json`:
   - `orders_enabled: true`
   - `twitch_channel` — имя вашего канала (без `#`)
   - `twitch_bot_username` — логин аккаунта бота
   - `twitch_client_id`, `twitch_client_secret`, `twitch_refresh_token` — из
     шага 3, `twitch_broadcaster_refresh_token` — из шага 3а
   - `orders_reward_title` — название награды (по умолчанию `Заказ героя`,
     не длиннее 45 символов)
   - `orders_reward_cost` — стоимость в баллах (по умолчанию 1000)
   - `orders_reward_prompt` — подсказка, которую зритель видит при
     активации
   - `orders_poll_interval_seconds` — как часто проверять новые активации
     (по умолчанию раз в 5 секунд)
   - `orders_storage_file` — файл, где хранятся заказы (по умолчанию
     `orders.json`)
   - `orders_queue_command` — команда показа очереди заказов, доступна всем
     (по умолчанию `!очередь`)
   - `heroes_link_command` — команда со ссылкой на таблицу героев, доступна
     всем (по умолчанию `!герои`)
   - `heroes_link_url` — ссылка, которую бот выводит в чат по команде
     `heroes_link_command`
   - `orders_heroes_file` — путь до словаря героев (по умолчанию
     `heroes.json`)
5. Скопируйте `heroes.example.json` в `heroes.json` рядом с `config.json`
   и настройте список доступных для заказа героев. В примере у всех героев
   `orderable` установлен в `true`. Локальный `heroes.json` исключён из Git.
   Каждая запись:
   ```json
   {
     "replay_hero": "Kerrigan",
     "display_name": "Керриган",
     "aliases": ["kerrigan", "керриган", "керри", "kerri"],
     "orderable": true
   }
   ```
   - `replay_hero` — внутреннее (движковое) имя героя из
     `replay.tracker.events`. Оно **не зависит от языка клиента игры**
     (в отличие от `m_hero` из `replay.details`), поэтому подходит, даже
     если вы стримите то с русским, то с английским клиентом. Проще всего
     узнать значение из собственных логов: утилита при каждом новом реплее
     пишет строку вида `герой=Kerrigan (локализованно: Керриган)` — в
     `replay_hero` идёт именно значение до скобок, не то, что в них.
   - `replay_hero_aliases` — необязательный список других движковых имён
     того же героя (пригодится, если Blizzard переименовали внутренний
     идентификатор при переработке героя, а старые реплеи всё ещё
     встречаются).
   - `display_name` — как называть героя в сообщениях бота.
   - `aliases` — варианты написания, которые могут набрать зрители (регистр
     и `ё`/`е` не важны, их можно не дублировать).
   - `orderable` — можно ли сейчас заказывать этого героя (`false` — если
     героя временно выключили из ротации заказов).

   **Важно:** если вы уже начали заполнять `replay_hero` локализованными
   (например, кириллическими) именами — их нужно пересобрать на движковые.
   Проще всего: один раз запустить утилиту, дождаться нескольких своих
   матчей и по логам `герой=... (локализованно: ...)` заменить значения.

**Награда управляется из конфига.** Twitch разрешает программе управлять
только наградами, которые она сама создала, поэтому заводить награду
вручную в панели Twitch не нужно (а если там уже есть награда с таким же
названием — утилита не сможет создать свою: переименуйте старую или смените
`orders_reward_title`). Название, стоимость и подсказка при каждом запуске
выставляются из `config.json` — меняйте их там.

## Обновление поддержки новых патчей игры

Библиотека `heroprotocol` понимает конкретные билды игры. Если после
крупного патча парсинг перестанет работать (или в логе будет много
предупреждений о неизвестном билде), нужно обновить папку
`vendor/heroprotocol` свежей версией с
https://github.com/Blizzard/heroprotocol. Утилита и так использует
fallback на ближайший известный билд, так что чаще всего обновление не
критично — формат `replay.details` очень редко меняется.
# Результаты матчей в чате

Уведомления включены по умолчанию (`match_results_enabled: true`) и работают
независимо от `orders_enabled` и словаря героев. Для чата заполните
`twitch_channel`, `twitch_bot_username`, `twitch_client_id`,
`twitch_client_secret`, `twitch_refresh_token`. Токен канала для уведомлений
не требуется.

Шаблон `match_results_format` по умолчанию:
`{result} на карте «{map}». Счёт сессии: {wins}–{losses}.`
Счёт включает только новые матчи после запуска программы. Матчи с неизвестным
результатом или разными результатами отслеживаемых аккаунтов не объявляются;
неоднозначные матчи также не учитываются в статистике и заказах.

В `maps.json` заполните значения переводами; ключи должны точно совпадать с
названиями из реплеев (их можно увидеть в логе `карта=...`). При необходимости
добавьте ключи для русского или другого языка клиента. Пустое значение или
отсутствующий ключ оставляют исходное название. `maps_file` задаётся относительно
папки конфигурации. После редактирования перезапустите программу.

Во время отключения чата сообщения ожидают в памяти и отправляются по порядку
после подключения. Ошибки записи в соединение вызывают повторную попытку.
При перезапуске очередь теряется; при обрыве в момент отправки возможен дубль,
поскольку подтверждения доставки нет.
